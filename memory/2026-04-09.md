## [主题] stock-quant 项目全面分析（2026-04-09 20:47）

项目路径：`/Users/mac/openclaw-projects/stock-quant/`
用户请求：全面分析项目存在的问题和改进建议。

### 一、架构层面

**1. 多数据源 fallback 链路设计合理**
```
TuShare → EastMoney → Tencent → Mock
```
每层都有兜底，但 mock 模式下 Web 界面会显示"数据来源：模拟数据"，用户需自行判断。

**2. 回测引擎分层清晰**
- `_build_config`：策略参数 vs 回测参数分离
- `_prepare_dataframe`：数据标准化（去重、排序、类型转换）
- `_simulate_trades`：事件驱动撮合，支持止损/止盈/移动止损/ATR止损/分批止盈
- `_calculate_metrics`：完整的指标体系（夏普/索提诺/卡曼比率）
- `walk_forward`：滚动窗口验证，防过拟合

**3. 指标计算原地修改 DataFrame**
默认 `copy=False`，直接修改输入 DataFrame。这是性能优化，但有副作用——同一份 df 被多次 `calculate()` 后指标列会重复叠加。`SignalGenerator.analyze()` 内部做了缺失检测和按需计算，但回测引擎每次都 `prepared_df.copy()` 后再计算，存在重复。

### 二、代码质量问题

**🔴 严重问题**

1. **`_calc_wr` 指标值域 bug**（calculator.py）
   ```python
   df[f'wr{period}'] = -100 * (highest - df['close']) / diff
   df[f'wr{period}'] = df[f'wr{period}'].fillna(-50)
   ```
   WR 指标公式是对的（-100~0），但 `.fillna(-50)` 把 NaN 填成了 -50（中值）。更严重的是：
   - 后续 `signal_generator.py` 的 `_analyze_wr` 用 `abs(wr6)` 判断，abs(-50)=50，既不是超买也不是超卖
   - 但注释说 `abs(wr6) > 80` 是超卖，这是反的——WR 接近 -100（绝对值大）才超卖
   - 正确逻辑：abs(wr6) > 80 应该是超卖→买入，但实际数值含义被 fillna 破坏

2. **API Key 明文硬编码**（多处）
   - `tushare` 模块直接 `os.environ.get("TUSHARE_TOKEN", "")`
   - 没有从 `config/production.env` 读取的示例逻辑（README 有写，但代码没实现）
   - `MINIMAX_API_KEY` 只在 cc_code 中使用，stock-quant 没有用到

3. **未处理变量引用**（signal.py routes）
   ```python
   if eastmoney:  # ← 前面已经从 clients 取了赋值给局部变量 eastmoney
       rt = eastmoney.get_realtime(code)
   ```
   `get_monitor_signals` 路由中 `eastmoney` 是从 `_clients` 取的且有 if guard，但信号路由里忘了赋值就用了。

**🟠 中等问题**

4. **Walk-forward 资金复利 vs 固定资金混淆**
   ```python
   current_capital = segment_metrics.end_capital  # 用上期期末资金
   ```
   walk_forward 每期用上一期赚的钱继续投资（复利），但回测结果汇总时：
   ```python
   aggregate_metrics = self._calculate_metrics(all_trades, combined_equity_curve, initial_capital)
   ```
   用 `initial_capital` 做分母算总收益，但实际资金在滚动中不断增加。这个指标不能直接和单次回测比较（分母不同）。

5. **MultiFactorStrategy 的 `_build_analysis_frame` 重复计算**
   这个方法每次调用都会重新计算所有中间指标，但 `generate_signals` 和 `get_diagnostics` 都调用了它——一次信号生成+一次诊断=重复计算。对于 5000 条数据的股票，浪费 1 倍时间。

6. **布林带 RSI 计算覆盖问题**
   ```python
   df["rsi"] = (100 - (100 / (1 + rs))).fillna(100)  # ← fillna(100) 超买！
   ```
   `BollReversionStrategy._build_analysis_frame` 里手动计算 RSI 用 `fillna(100)`，但正常 RSI 超买是 70-80。fillna(100) 导致 reversion_score 永远是 0（价格不会超过 100）。

7. **`_calc_rsi` 的 `np.where` 链过于复杂**
   ```python
   rs = np.where((gain == 0) & (loss == 0), np.nan,
            np.where(loss == 0, np.inf, gain / loss))
   df[f'rsi{period}'] = np.where(
       np.isnan(rs), 50,  # 价格不动→中性50
       np.where(np.isinf(rs), 100, 100 - (100 / (1 + rs)))
   )
   ```
   这个逻辑是对的：gain==0 & loss==0 → 中性50；loss==0（只有涨）→ RSI=100。但可读性差，建议拆成子函数。

**🟡 轻微问题**

8. **回测引擎不支持空头/做空**
   策略只生成 BUY/SELL/HOLD，实际模拟的是"买入→持有→卖出"，不支持做空。A股不能做空所以短期内不是问题，但限制了策略测试范围。

9. **参数命名不一致**
   - CLI 参数用 `commission`（无 `_rate`），config 里用 `commission_rate`
   - `_parse_backtest_params` 和 `_build_config` 参数名映射可能对不上

10. **walk_forward 的 `max_evals=50` 太小**
    `multi_factor` 策略默认参数范围很大（5个因子权重各3个选项+买卖阈值3+4个=20+组合），50次 evaluations 可能搜不到有意义的参数空间。

### 三、测试覆盖问题

11. **没有回测引擎的单元测试**
    `test_backtest_engine.py` 不存在（README 说 CI 跑 `tests.test_backtest_engine`，但文件可能没提交）。回测逻辑完全依赖人工验证。

12. **CI 只跑语法检查 + 一个测试**
    ```yaml
    - run: ./venv/bin/python -m pytest tests/test_backtest_engine.py
    ```
    如果 `test_backtest_engine.py` 不存在，CI 就 pass 了（0 failures）。`test_indicator_calculator.py` 倒是存在且较完整。
